# UI tasks

Working checklist for the chat surface. Companion to [tasks.md](tasks.md), which covers the RAG
pipeline. Split out because that file is the retrieval checklist and closes with its own Deferred
section; this is a separate track over the same corpus.

Everything below touches `app/page.tsx`, `app/layout.tsx` or `app/globals.css`, except Task 5b,
which also reaches the feedback route and the schema. `app/page.tsx` is the entire UI: one client
component, 184 lines at the start of this work and 578 at the end.

Before implementing, read the relevant guide in `node_modules/next/dist/docs/01-app/` — per
`AGENTS.md` this Next.js differs from training data. Everything that shipped stayed inside the
existing `"use client"` tree; no server component was added.

## Verdict on the three suggestions

| Suggestion | Verdict |
| --- | --- |
| FAQ section for self-service | **Merge into starter questions** (Task 3). A hand-written FAQ is rejected — see below. The zero-maintenance alternative was sized in Task 6 and dropped. |
| 3–4 pre-typed popular queries | **Keep** — Task 3. Cheapest change with the largest effect. |
| Improve the thumbs up/down | **Keep, in two halves** — Task 5 (confirmation, ~4 lines) and Task 5b (why it was bad, needs a migration). |

### Why a hand-written FAQ is rejected

A FAQ with its own answer text is a second copy of `content/docs/`. This repo has already decided
against that twice — `lib/rag/prompt.ts` keeps one copy of the prompt because "a second copy of this
text would silently drift", and tasks.md names docs going stale as "the real failure mode of a
support agent". Curated FAQ answers also bypass the two things the product is built on: citations
with an `updated` date, and the escalation gate. A wrong FAQ answer has no source link and no way to
be caught by the eval.

What the suggestion is actually reaching for — *let people self-serve without a round trip* — is
served by Task 3: questions that are one click from a cited answer. Task 6 sized the fuller version
— browsing the real corpus out of the `chunks` table — and dropped it; the reasoning is kept there.

## Task 2 — Fix the two layout bugs already in the file — DONE

**Files:** `app/globals.css`, `app/page.tsx`

- [x] Delete `font-family: Arial, Helvetica, sans-serif` from the `body` rule in `globals.css`.
      `layout.tsx` loads Geist and wires it to `--font-sans` in `@theme inline`; that `body` rule
      sits after `@import "tailwindcss"` and overrides it, so the app renders in Arial and the font
      loading is dead weight. Replace with `font-family: var(--font-sans)`.
- [x] Make the composer `sticky bottom-0` on the `<form>` instead of `fixed` on the `<input>`.
      A `fixed` element leaves the flex flow, so the parent's `mx-auto` does not centre it and
      `w-full max-w-2xl` is measured against the viewport — it only looks centred because it happens
      to land on its static position. On a narrow screen it overflows the container's `px-4`.
      `sticky` keeps it in flow and the existing centring and padding just apply, which also deletes
      `fixed`, `w-full`, `max-w-2xl` and `mb-8` from the input.

Deletion, not addition — both fixes remove code.

### Done when

The page renders in Geist, and the composer stays inside the column at 375px wide.

## Task 3 — Starter questions on the empty state — DONE

**File:** `app/page.tsx`

The empty state is currently a blank page with a floating input and no indication of what the agent
knows. This is also the only cheap lever on the one failure the pipeline cannot fix: tasks.md's
Deferred section shows no `MIN_SIMILARITY` separates in-scope from out-of-scope questions
(correct answers bottom out at 0.638, out-of-scope reaches 0.714). Advertising scope up front
prevents the out-of-scope question instead of trying to detect it after the fact.

### Steps

- [x] `const STARTERS = [...]` — 4 strings, top of `app/page.tsx`. Take them from `eval/questions.ts`,
      which is already phrased the way users type and already known to retrieve: one billing, one
      error code, one setup, one policy. e.g. `"is there a free trial"`,
      `"why did my sync fail with 401"`, `"how do i set up okta saml"`, `"can I get a refund"`.
- [x] Render only when `messages.length === 0`: an `<h1>` naming the product plus one line of scope,
      and the four as buttons.
- [x] Click → `setInput(q)` and focus the input. This is what was asked for ("straight to input, no
      typing") and keeps the question editable.
      **Superseded by Task 7:** clicking now sends. Landing the text in the box and stopping read as
      a dead end — nobody edited the starter, they just pressed Enter.

Hardcoded, not read from the `retrievals` table. There is no traffic yet, and a DB round trip per
page load to render four strings is not worth it — revisit when `retrievals` has enough rows that
"popular" means something.

### Done when

A first-time visitor can get a cited answer without typing, and can see what the agent covers
before asking.

## Task 6 — Browse the corpus instead of an FAQ — DROPPED

A panel listing the knowledge base, generated from the `chunks` table so it could not drift from
what retrieval actually searches. Dropped before it was built, for a reason the data made obvious:

```
chunks: 237 | docs: 15 | urls: 15 | headings: 225
```

**225 distinct headings, 15 URLs.** `url` comes from doc frontmatter; there are no per-section
anchors. So the heading-level version links all 28 sections of *Troubleshooting Sync Failures* to
the same page — a wall of 225 rows pointing at 15 destinations.

That leaves the doc-level version, 15 titles by category. The argument for it was scope display:
tasks.md shows out-of-scope detection is unsolved and unfixable by threshold (correct answers floor
at 0.638, out-of-scope reaches 0.714 — *"do you sync to google sheets"* scores **higher** than real
questions), so showing coverage up front beats detecting it after. But that argument needs section
or content detail to land. A title reading "Destinations" does not tell anyone Snowflake is in and
Google Sheets is out — you would have to open the page, and `docs.meridiandata.com` is fictional.

Fifteen category names is roughly what Task 3's starters already imply. Not worth a server
component and a query.

## Note — citations link to page tops, not sections

Found while sizing Task 6, and it outlives it. Every citation under an answer, and every link in
the model's markdown, resolves to a whole document. The chunker knows the exact section
(`headingPath`), the link throws it away.

Fixing it means slugifying `headingPath` into `url#slug` in `lib/rag/chunk.ts` and re-ingesting —
tasks.md Tasks 3–4, not a UI change. The trigger is the docs actually being published somewhere:
against a fictional host, a precise anchor is as dead as a vague one. Worth doing on the same day
that stops being true, because "cite the section you used" is the product's main claim and it
currently lands the reader on a page top to find it themselves.

## Task 7 — A design, not a default — DONE

**Files:** `app/page.tsx`, `app/layout.tsx`, `app/globals.css`

Tasks 1–5b fixed what was broken and left what was generic. The result was the create-next-app chat
demo: Geist, zinc, pill buttons, a centred column with 550px of empty white below it, and the
provenance this product is built on filed as 12px grey footnotes.

Shipped over three rounds of review. The first two are recorded here only where they explain why
something is the way it is — the intermediate states are in git, not in this file.

### The type system — kept

- [x] Source Serif 4 for questions and answers, because an answer here is a piece of documentation
      and reads like one. Archivo for chrome. Source Code Pro only where the content is literally
      machine output: similarity scores, dates, error codes. Geist is gone.

This was the one part of the first pass that survived review unchanged.

### The palette — rewritten

The first pass built a nautical-chart palette off the product's name: pale green-grey paper, chart
navy, and magenta, which on a chart means a navigational caution. Reviewed and rejected — the green
cast and the pink read as a costume on a support tool.

- [x] White ground, neutral greys, one blue at `#1f5fd0`. No tint in the greys.
- [x] Semantic tokens that flip in one `prefers-color-scheme` query, so no element carries a `dark:`
      variant. One definition per colour instead of two per element. This survived from the first
      pass and is why the repalette touched only `:root`.

### Structure

- [x] **Questions are headings, answers are body.** The user bubble is gone. A question sits flush
      at the margin and its answer runs beneath it, so the transcript reads as a Q&A document with
      its evidence attached rather than as a thread.
- [x] **Full-height layout**: header, transcript, composer pinned to the bottom of the viewport.
- [x] **Starters are bordered rows that send on click**, sentence-cased with question marks. Three
      things were wrong with the first version: pills read as tags, lower-case fragments did not
      read as questions, and clicking only filled the box. `STARTERS` now carries the display
      phrasing; `eval/questions.ts` keeps the raw lower-case strings, because rewording those would
      invalidate every capture in `eval/search-queries.json`.
- [x] Sources show the title left and the `updated` date right in the machine face. The date is the
      part a reader cannot judge for themselves, so it gets a column rather than trailing the title.

### Feedback

- [x] **"Was this helpful?" with two thumb buttons.** The bare pair of controls never said what it
      was asking. The icon is one SVG path flipped on the Y axis for the down vote.
- [x] **The comment box is a native `<dialog>`.** It was an inline input that pushed the transcript
      around and competed with the answer above it. `showModal()` brings the focus trap, Esc, the
      inert background and correct stacking with no library and no new state beyond the message id.
      The down vote is written before the dialog opens, so dismissing it costs nothing.

### Gotchas found

- **`display: flex` on a `<summary>` removes the disclosure marker in Chrome.** The retrieval panel
  looked like static text. It supplies its own caret, reusing the `›` that separates heading paths.
- **`--rule` is too faint to bound a control.** A hairline between rows is decorative and exempt,
  but a composer border at `--rule` measured 1.4:1 against the page where WCAG 1.4.11 wants 3:1.
  `--edge` is a separate token for control boundaries, not one colour used at two strengths.
- **A fill cannot bound a control on a white page.** Reaching 3:1 against `--paper` needs a fill
  around 25% luminance — a dark grey box, not a text field. Controls keep a border.
- **An inline `<code>` breaking across lines** splits `SYNC-201` in half, which is the one string a
  reader came to copy. `white-space: nowrap` on `.answer code`, `pre` on `.answer pre code`.
- **`showModal()` throws if the dialog is already open.** The effect is driven by a
  `string | null`, which cannot transition id → id, so it never double-opens.
- **Streamdown renders UI this project never styled.** Clicking a citation inside an answer opens
  Streamdown's own external-link confirmation, and a fenced code block gets its own action bar.
  Both are built on shadcn's token names — `bg-background`, `bg-muted`, `bg-primary`, `bg-sidebar`,
  `text-muted-foreground`, `border`. The original `globals.css` defined only background and
  foreground, so the rest generated no utilities at all and that UI rendered with no surface. They
  are mapped onto this palette in `@theme inline` now. Streamdown also brings its own
  `backdrop-blur`; the `[data-streamdown="…"]` rules drop it. Unlayered rules beat the utilities
  from `@import "tailwindcss"`, which sit in a cascade layer, so no `!important` is needed.
- **Tailwind v4 defaults a bare `border` to `currentColor`.** Streamdown writes bare `border` on
  that modal, which outlined it in body-text ink. The `@layer base` shim sets the default border
  colour to `--rule`; every border in `page.tsx` names its colour, so nothing else moves.

### Verified

Rounds one and two were shot in light, dark and at 390px with Playwright against the dev server,
including a conversation state rendered by injecting real markup into the live page so the compiled
stylesheet and fonts applied — the alternative was spending the 20/day Gemini quota. **Round three
was not shot**; it is lint- and build-clean but has not been looked at in a browser.

### Still true

No new dependencies. `@tailwindcss/typography` stays unused — `.answer` styles Streamdown's plain
elements with descendant selectors, which is fewer bytes than a plugin and does not fight its
utility classes.

## Task 8 — Rebuild the empty state from a supplied design — DONE

**Files:** `app/page.tsx`, `app/globals.css`

A mockup of the landing state was handed over as the reference. Task 7's output was a typographic
page; this is a product page, and the mockup is better at the job — a first-time visitor sees what
the agent covers as four concrete things rather than as one sentence.

### Taken from the reference

- [x] **Header**: wordmark with a mark, a divider, and a status pill on the right.
- [x] **Centred hero** with a chat-bubble illustration above the headline. Inline SVG, no asset.
      The headline is *"What can we help you with?"* — the scope list it replaced (*"Ask about a
      sync, an error code, a connector, or your bill"*) was the third thing on screen saying the
      same thing, after the four cards and the line below it. The scope claim that matters,
      "only from the Meridian Sync documentation", is in the subheading and stays. Task 3's
      argument for advertising scope survives: the cards make it concrete where a list of
      categories only gestured at it.
- [x] **Four cards in a 2×2 grid**, each a tinted round icon, the question, a line saying what the
      answer will cover, and an arrow. Clicking sends. Replaces Task 7's plain rows.
- [x] **Pill composer** with a sparkle mark and a filled `Ask` button, on a periwinkle band.
- [x] **Palette**: white ground, navy ink, one royal blue, a faint dot field at either edge.

### Deliberately not taken

- **The reference's rounder geometric sans.** Archivo is already loaded and was the one thing about
  Task 7 that got a "I like the fonting". If the friendlier feel is wanted, swapping Archivo for
  Plus Jakarta Sans is two lines in `layout.tsx`.
- **Serif for answer prose stays.** The reference only shows the landing state; nothing in it
  argues against the reading face, and `.answer` is where the long text lives.
- **The wave shape** is a gradient band instead. One path of decoration behind a sticky composer
  was not worth the layering it needed.
- **The gear icon for SSO** is a padlock. A gear needs more than two paths to read at 18px, and a
  padlock is the truer icon for single sign-on anyway.
- **"Your queries are private and only used for support purposes."** Untrue as written — every
  question is written to the `retrievals` table with the sections it matched. The line now says
  that.
- **A hardcoded "Online" pill.** A green dot that can never go out is decoration. It reads the
  `error` from `useChat` and says "Unavailable" when the last request failed, which is the only
  status the page actually knows.

### Gotchas found

- **Tailwind cannot see a class name built at runtime.** The four card tints come from data, so
  `bg-[${accent}]` would compile to nothing. They are inline `style` with `color-mix`, which is
  also how one value drives both the icon colour and its 13% tint.
- **`max-w-3xl` wrapped the 401 card title onto two lines**, which unbalanced the grid — but
  widening `<main>` to `max-w-4xl` then left the transcript 112px to the left of the composer's
  `max-w-2xl` pill. The width is conditional now: `max-w-4xl` for the card grid, `max-w-2xl` once
  a conversation starts, and the `.answer` block lost its own 68ch cap because the column is the
  measure.
- **`box-sizing: border-box` puts `px-5` inside `max-width`.** A `max-w-2xl` form beside a
  `max-w-2xl` main still sat 20px to its left. The composer is wrapped in the same padded
  `max-w-2xl` box `<main>` uses, so both resolve to one content edge.

### Verified

Light, dark and 390px shot with Playwright against the dev server. The conversation state was not
re-shot this round — only its palette changed, and that is driven by the same tokens as the landing
state.

## Order and cost

Tasks 1, 2 and 5 were under thirty minutes together and all three were fixes to things already
wrong. Task 3 is the requested feature. Task 4 is the actual "upgrade the UI". 5b cost a migration
and is what makes a thumbs-down diagnosable. Task 6 was dropped. Nothing here is outstanding.

No new dependencies for any of it. `clsx` and `@tailwindcss/typography` are already installed and
unused by `page.tsx` if conditional classes or prose defaults get verbose.

## Not doing

- **Hand-written FAQ answers** — second source of truth, no citations, no eval coverage. See above.
- **Suggested follow-up questions after an answer** — needs another model call per turn against a
  20/day free-tier cap (tasks.md, Task 11).
- **Conversation history sidebar / persistence** — already deferred in tasks.md; the UI cannot have
  it before the storage does.
- **Dark mode toggle** — `prefers-color-scheme` already covers it and every class has its `dark:`
  variant. A toggle adds state, storage and a hydration mismatch to fix.
- **An `/admin` view of the thumbs-down queue** — deferred in tasks.md for the same reason: a SQL
  query and a terminal do this until someone who cannot run `pnpm` has to operate it.
- **Component library, message virtualisation, streaming skeletons** — 184 lines and one route do
  not need a component tree, and the transcript is short enough to render whole.
