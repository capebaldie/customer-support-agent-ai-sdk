# UI tasks

Working checklist for the chat surface. Companion to [tasks.md](tasks.md), which covers the RAG
pipeline. Split out because that file is the retrieval checklist and closes with its own Deferred
section; this is a separate track over the same corpus.

Everything below touches `app/page.tsx`, `app/layout.tsx` or `app/globals.css` unless stated.
`app/page.tsx` is currently the entire UI: 184 lines, one client component.

Before implementing, read the relevant guide in `node_modules/next/dist/docs/01-app/` — per
`AGENTS.md` this Next.js differs from training data. Task 6 is the only one that adds a server
component (`01-getting-started/05-server-and-client-components.md`).

## Verdict on the three suggestions

| Suggestion | Verdict |
| --- | --- |
| FAQ section for self-service | **Merge into starter questions** (Task 3). A hand-written FAQ is rejected — see below. Optional zero-maintenance version in Task 6. |
| 3–4 pre-typed popular queries | **Keep** — Task 3. Cheapest change with the largest effect. |
| Improve the thumbs up/down | **Keep, in two halves** — Task 5 (confirmation, ~4 lines) and Task 5b (why it was bad, needs a migration). |

### Why a hand-written FAQ is rejected

A FAQ with its own answer text is a second copy of `content/docs/`. This repo has already decided
against that twice — `lib/rag/prompt.ts` keeps one copy of the prompt because "a second copy of this
text would silently drift", and tasks.md names docs going stale as "the real failure mode of a
support agent". Curated FAQ answers also bypass the two things the product is built on: citations
with an `updated` date, and the escalation gate. A wrong FAQ answer has no source link and no way to
be caught by the eval.

What the suggestion is actually reaching for — *let people self-serve without a round trip* — is
served by Task 3 (questions that are one click from an answer) and, if that is not enough, Task 6
(browse the real corpus, generated from the `chunks` table, so it cannot go stale).

## Task 2 — Fix the two layout bugs already in the file

**Files:** `app/globals.css`, `app/page.tsx`

- [ ] Delete `font-family: Arial, Helvetica, sans-serif` from the `body` rule in `globals.css`.
      `layout.tsx` loads Geist and wires it to `--font-sans` in `@theme inline`; that `body` rule
      sits after `@import "tailwindcss"` and overrides it, so the app renders in Arial and the font
      loading is dead weight. Replace with `font-family: var(--font-sans)`.
- [ ] Make the composer `sticky bottom-0` on the `<form>` instead of `fixed` on the `<input>`.
      A `fixed` element leaves the flex flow, so the parent's `mx-auto` does not centre it and
      `w-full max-w-2xl` is measured against the viewport — it only looks centred because it happens
      to land on its static position. On a narrow screen it overflows the container's `px-4`.
      `sticky` keeps it in flow and the existing centring and padding just apply, which also deletes
      `fixed`, `w-full`, `max-w-2xl` and `mb-8` from the input.

Deletion, not addition — both fixes remove code.

### Done when

The page renders in Geist, and the composer stays inside the column at 375px wide.

## Task 3 — Starter questions on the empty state

**File:** `app/page.tsx`

The empty state is currently a blank page with a floating input and no indication of what the agent
knows. This is also the only cheap lever on the one failure the pipeline cannot fix: tasks.md's
Deferred section shows no `MIN_SIMILARITY` separates in-scope from out-of-scope questions
(correct answers bottom out at 0.638, out-of-scope reaches 0.714). Advertising scope up front
prevents the out-of-scope question instead of trying to detect it after the fact.

### Steps

- [ ] `const STARTERS = [...]` — 4 strings, top of `app/page.tsx`. Take them from `eval/questions.ts`,
      which is already phrased the way users type and already known to retrieve: one billing, one
      error code, one setup, one policy. e.g. `"is there a free trial"`,
      `"why did my sync fail with 401"`, `"how do i set up okta saml"`, `"can I get a refund"`.
- [ ] Render only when `messages.length === 0`: an `<h1>` naming the product plus one line of scope,
      and the four as buttons.
- [ ] Click → `setInput(q)` and focus the input. This is what was asked for ("straight to input, no
      typing") and keeps the question editable.

Hardcoded, not read from the `retrievals` table. There is no traffic yet, and a DB round trip per
page load to render four strings is not worth it — revisit when `retrievals` has enough rows that
"popular" means something.

### Done when

A first-time visitor can get a cited answer without typing, and can see what the agent covers
before asking.

## Task 4 — Make the transcript readable

**File:** `app/page.tsx`

User and assistant turns are visually identical today: a bold `You` / `Assistant` label over prose.
This is the highest visual return in the file.

### Steps

- [ ] Give the user turn a tinted, rounded, self-end bubble; leave the assistant turn full width
      (it carries markdown, tables and citation lists — a bubble would fight it)
- [ ] Quieten the retrieval `<details>` panel: smaller text, muted border. **Keep it.** Task 7 in
      tasks.md built it as the debugger that distinguishes *retrieval returned the wrong chunks*
      from *the model ignored the right ones*, and those have different fixes. It is already
      collapsed by default; make it look like a footnote rather than content.
- [ ] Auto-scroll: a sentinel `<div>` after the last message plus
      `useEffect(() => ref.current?.scrollIntoView({ block: "end" }), [messages])`. Long answers
      currently stream off-screen and the user has to chase them.
- [ ] Stop button while `busy`. `useChat` already returns `stop` (verified in
      `node_modules/@ai-sdk/react/dist/index.d.ts`); a long stream is currently uninterruptible.
      One button next to the composer, replacing nothing.

### Done when

You can tell at a glance who said what, the newest text is on screen, and a runaway answer can be
cancelled.

## Task 5b — Feedback: capture *why* a thumbs-down happened — OPTIONAL

**Files:** `app/page.tsx`, `app/api/feedback/route.ts`, `lib/db/schema.ts`, new migration

tasks.md defers per-part escalation with "wait for a thumbs-down that shows it happening". A bare
`down` in the `retrievals.feedback` column cannot show anything happening — the signal the next
piece of work is gated on carries no diagnostic content. This is the one feedback change with a
concrete, already-documented payoff.

### Steps

- [ ] `comment: text()` on `retrievals`, nullable. `pnpm db:generate && pnpm db:migrate`
- [ ] Widen the zod body in the feedback route: `comment: z.string().trim().max(500).optional()`.
      It is a trust boundary — keep it validated and length-capped. Same `messageId` update path.
- [ ] On `down` only, reveal a one-line optional input ("What was wrong?") that POSTs to the same
      endpoint. Skipping it still records the `down`.

### Done when

A thumbs-down can tell you which of *wrong retrieval*, *ignored context* or *half-answered* it was.

## Task 6 — Browse the corpus instead of an FAQ — OPTIONAL

**Files:** `app/page.tsx`, one new server component

Only if Task 3's four starters prove too narrow. A collapsible panel listing the 15 docs and their
section headings, from `select distinct docTitle, url, category, headingPath from chunks` — the same
rows retrieval searches, so it cannot drift from what the agent can actually answer, and it needs no
content maintenance. Each heading clicks through to `url`, exactly like the citations under an
answer already do.

The DB query means this is a server component composed into the client chat, not part of
`page.tsx`'s `"use client"` tree — read
`node_modules/next/dist/docs/01-app/02-guides/server-and-client-boundary.md` first.

### Done when

A visitor can see every topic in the knowledge base without asking a question.

## Order and cost

Tasks 1, 2 and 5 are under thirty minutes together and all three are fixes to things already wrong.
Task 3 is the requested feature and the one worth doing next. Task 4 is the actual "upgrade the UI".
5b and 6 wait for a reason.

No new dependencies for any of it. `clsx` and `@tailwindcss/typography` are already installed and
unused by `page.tsx` if conditional classes or prose defaults get verbose.

## Not doing

- **Hand-written FAQ answers** — second source of truth, no citations, no eval coverage. See above.
- **Suggested follow-up questions after an answer** — needs another model call per turn against a
  20/day free-tier cap (tasks.md, Task 11).
- **Conversation history sidebar / persistence** — already deferred in tasks.md; the UI cannot have
  it before the storage does.
- **Dark mode toggle** — `prefers-color-scheme` already covers it and every class has its `dark:`
  variant. A toggle adds state, storage and a hydration mismatch to fix.
- **An `/admin` view of the thumbs-down queue** — deferred in tasks.md for the same reason: a SQL
  query and a terminal do this until someone who cannot run `pnpm` has to operate it.
- **Component library, message virtualisation, streaming skeletons** — 184 lines and one route do
  not need a component tree, and the transcript is short enough to render whole.
